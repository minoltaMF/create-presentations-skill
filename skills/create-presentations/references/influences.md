# Influences and reuse boundary

This skill is an original, provider-neutral workflow. It combines reviewed patterns without bundling upstream runtimes.

## Referenced methods

- **codex-ppt-skill** — MIT, https://github.com/ningzimu/codex-ppt-skill
  - Retain outline/style/sample thinking, per-slide image jobs, full-slide visual assembly, notes, and visual QA.
  - Do not inherit fixed Provider configuration, mandatory orchestration assumptions, credentials, or arbitrary path behavior.
- **Bento** — MIT, https://github.com/nyblnet/bento
  - Retain portable single-file HTML and presenter interaction ideas.
  - Do not bundle its editor, CRDT, relay, updater, or file-permission runtime.
- **PptxGenJS and native presentation tooling**
  - Retain deterministic editable text, tables, charts, notes, and template assembly.
- **Template-following and Artifact Tool workflows**
  - Retain master/layout inspection, source-deck fidelity, full rendering, and overlap checks.
- **Baoyu slide workflows**
  - Retain content planning, visual storytelling, contact-sheet review, and style exploration.
- **Render-Inspect-Revise research such as DeepPresenter/PPTAgent**
  - Retain the evaluation loop, not an unreviewed executable sidecar.

## Original synthesis

The distinctive workflow is:

`flexible page narratives -> one deck-level Design DNA -> independent text/image model routing -> Native/Visual/Hybrid/Template/HTML route choice -> visible-copy integrity -> human-review-first revision -> evidence-backed delivery`

Copy upstream code only after checking the exact license and retaining attribution. Method inspiration alone does not require bundling upstream source.
