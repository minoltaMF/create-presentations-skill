# Influences and reuse boundary

This skill is an original, provider-neutral workflow. It combines reviewed patterns without bundling upstream runtimes.

## Referenced methods

- **codex-ppt-skill** — MIT, https://github.com/ningzimu/codex-ppt-skill
  - Retain outline/style/sample thinking, stable per-slide jobs and states, backend provenance, full-slide visual assembly, notes, and visual QA.
  - Do not inherit fixed provider configuration, mandatory delegation, unnecessary approval gates, credentials, or arbitrary path behavior.
- **Bento** — MIT, https://github.com/nyblnet/bento
  - Retain portable single-file HTML and presenter interaction ideas.
  - Do not bundle its editor, CRDT, relay, updater, or file-permission runtime.
- **Frontend Slides** — MIT, https://github.com/zarazhangrui/frontend-slides
  - Retain the practice of comparing materially different visual previews and describing repeatable Design DNA.
  - Do not copy its templates, runtime, or gallery screenshots.
- **ppt-agent-skill** — MIT, https://github.com/Akxan/ppt-agent-skill
  - Retain broad style-family coverage, suitability mapping, and explicit failure constraints.
  - Do not copy its style mocks, brand imitations, runtime, or prompt files.
- **PptxGenJS and native presentation tooling**
  - Retain deterministic, fast editable text, tables, charts, notes, and template assembly.
- **ppt-master** — MIT, https://github.com/hugohe3/ppt-master
  - Retain route-specific planning, vector/native authoring discipline, project directories, and blocker-versus-advisory quality checks.
  - Do not bundle its runtime or make its larger startup cost the default when a direct native builder produces comparable results.
- **guizang-ppt-skill** — AGPL-3.0, https://github.com/op7418/guizang-ppt-skill
  - Retain only method-level lessons for disciplined layout, presenter notes, browser acceptance, audience-screen sync, and static fallbacks.
  - Do not copy its code, template, or runtime into this MIT repository; do not present an image-wrapped PPTX as editable.
- **Legacy local `pptx` Skill** — source provenance unconfirmed
  - Retain the evidence that compact direct native generation can be both fast and visually competitive.
  - Do not copy its files, missing-dependency assumptions, or weak delivery gates.
- **Template-following and Artifact Tool workflows**
  - Retain bundled-runtime discovery, master/layout inspection, source-deck and theme fidelity, full rendering, overflow checks, and artifact delivery discipline.
  - Do not copy or pin a versioned plugin runtime; locate and use the host-provided current runtime when available.
- **Baoyu slide workflows**
  - Retain content planning, visual storytelling, contact-sheet review, and style exploration.
- **Render-Inspect-Revise research such as DeepPresenter/PPTAgent**
  - Retain the evaluation loop, not an unreviewed executable sidecar.

## Original synthesis

The distinctive workflow is:

`flexible page narratives -> one deck-level Design DNA -> independent text/image model routing -> Native/Visual/Hybrid/Template/HTML route choice -> visible-copy integrity -> human-review-first revision -> evidence-backed delivery`

Copy upstream code only after checking the exact license and retaining attribution. Method inspiration alone does not require bundling upstream source.
